Put Flow before the action.

Your FJP access is confirmed. The next step is to connect one consequential production action to the judgment loop.

1. Check your email for the Flow key

Your key begins with fjp_live_. Store it securely. It authenticates calls to the Flow judgment/control service.

2. Start with one action

Pick a place where an agent can create real consequences: send, spend, approve, update, delete, deploy, transact or commit.

agent proposes action ↓ FJP ↓ application enforces judgment ↓ action

3. Make the first judgment call

curl -X POST https://resolve.flowinfo.co/api/v1/tools/judge \ -H "Authorization: Bearer fjp_live_..." \ -H "Content-Type: application/json" \ -d '{"context":"Agent proposes a $12,000 refund. Autonomous authority: $5,000. Manager approval: absent."}'

Use the returned action and falsifier to determine whether the application proceeds, holds or escalates.

4. Close the loop when the outcome arrives

The original judgment includes a request_id. Associate the eventual outcome with it so the judgment can be resolved against what actually happened.

curl -X POST https://resolve.flowinfo.co/api/v1/outcomes \ -H "Authorization: Bearer fjp_live_..." \ -H "Content-Type: application/json" \ -d '{"request_id":"req_...","outcome":"confirmed"}'
Judgment → action → outcome → resolution.
That is the loop FJP brings to production agents.

5. Keep model billing on your account

Customer model inference remains customer-owned. Third-party model fees should be billed directly by the customer's provider, cloud account or private inference stack. Flow charges for the judgment/control layer.
