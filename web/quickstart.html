FJP Quickstart

Put Flow before the action.

The agent can think with any model. Before it changes something consequential, send the proposed action and relevant context to Flow for judgment.

01

Choose the actions Flow controls

Do not send every model call through FJP. Put it on the boundary where the agent receives authority to act.

  • send a message or external communication
  • move money, issue a refund, set a price or approve a transaction
  • modify or delete records
  • change production infrastructure or security state
  • make a consequential approval, denial or commitment
02

Use customer-owned inference

Production FJP is configured against inference you already pay for: your provider account, cloud account, private model, or inference gateway.

Flow does not include or subsidize third-party model usage. Your model provider bills you directly. Flow bills separately for its judgment/control service.

Flow's judgment implementation remains proprietary. Customer-owned inference does not expose Flow's prompts, methods, scoring, calibration, evaluators or orchestration.

03

Get a Flow key

Production access is configured around the actions your agents take and your inference environment. Once enabled, you receive a key beginning with fjp_live_.

Request production access
04

Send the proposed action to judge

Include the proposed action and only the context Flow needs to judge it.

curl -X POST https://resolve.flowinfo.co/api/v1/tools/judge -H "Authorization: Bearer fjp_live_..." -H "Content-Type: application/json" -d '{"context":"Proposed action: issue a $12,000 refund. Customer is in good standing. Autonomous refund authority is $5,000."}'

Each response is a Judgment-Grounded Record with the signal, judgment, action, falsifier and a request_id.

{ "signal": "Customer requests a $12,000 refund", "judgment": { "assessment": "The proposed action exceeds autonomous authority", "confidence": 0.96 }, "action": { "directive": "ESCALATE for manager approval" }, "falsifier": { "condition": "Authorized manager approval is present", "checkable": true }, "request_id": "req_..." }
05

Enforce the returned action

Your application remains in control. Map the FJP directive to the behavior your agent is allowed to take.

PROCEED

Allow the tool or action to execute.

HOLD

Stop execution until the unresolved condition is cleared.

ESCALATE

Route to a human or higher-authority workflow.

if (judgment.action.directive.startsWith("PROCEED")) { await execute(proposedAction); } else if (judgment.action.directive.startsWith("ESCALATE")) { await humanReview(judgment); } else { await hold(proposedAction, judgment); }

The example above shows the control pattern, not a required client library.

06

Report what happened

When the relevant outcome becomes observable, send it back using the original request_id.

curl -X POST https://resolve.flowinfo.co/api/v1/outcomes -H "Authorization: Bearer fjp_live_..." -H "Content-Type: application/json" -d '{"request_id":"req_...","outcome":"manager_approved"}'

Outcome reporting supports later review and re-evaluation. Flow's internal evaluation and calibration methods remain proprietary.

07

Use MCP when the agent should call Flow directly

If your agent framework supports MCP, expose FJP as a tool rather than writing custom transport code.

endpoint: https://resolve.flowinfo.co/mcp auth: Authorization: Bearer fjp_live_...

The agent can call judge, weigh, and match as standard MCP tools.

OPTIONAL

Validate the record with FJP-CONF

FJP-CONF is the public, vendor-neutral conformance suite. It tests the observable Judgment-Grounded Record, not Flow's internal judgment method.

$ pip install fjp-conformance $ fjp-conform record.json --level 2
