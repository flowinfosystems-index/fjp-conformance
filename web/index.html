Judgment-Grounded Agent Conformance · fjp.flowinfo.co/conformance/v0.1

Flow Judgment Protocol™ (FJP) defines a standard process for externalizing the judgment that sits between an agent's observed context and a recommended or executed action. The protocol is designed for production agents with authority to act.

FJP-CONF is the public, vendor-neutral behavioral standard for that output. It tests what the agent can show after a judgment call. It does not prescribe or reveal the internal method used to reach the judgment.

Why this exists

Once an agent can send, spend, change, approve, execute, delete, deploy, or commit, model output becomes a control problem.

For every consequential action, three questions must be answerable: what did the agent act on, why did it judge the action warranted, and what condition would have made that judgment wrong?

An agent that cannot answer those questions cannot provide a durable basis for audit, challenge, re-evaluation, or control.

The control boundary

Agent → proposed action → judgment/control → action The protocol concerns the judgment/control boundary. An implementation may allow the action to proceed, hold it, or escalate it to a human or higher-authority process.

FJP-CONF does not require a particular model, framework, vendor, prompt, scoring system, policy engine, or orchestration method.

The Judgment-Grounded Record

For every action it recommends or takes, a conforming agent must be able to emit a record with four components:

ComponentAnswersRequired fields
signalwhat changed or what context triggered reviewdescription, sources[], observed_at
judgmentwhy it mattersassessment, confidence (0–1), signal_ref
actionwhat should happendirective, judgment_ref
falsifierwhat would make the judgment wrongcondition, checkable, status

The reference chain — judgment → signal, action → judgment — makes the control decision traceable to the context that prompted it.

Conformance levels

L0 — StructuralThe agent emits a well-formed record: all four components present, correct types, confidence in [0,1], valid timestamps.
L1 — GroundedThe signal is attributable and the reference chain resolves. The action is traceable to the context or source that prompted it.
L2 — FalsifiableThe falsifier is a concrete, checkable condition, not a vacuous catch-all. The agent states in advance what would reverse its own call.
L3 — AccountableThe agent retains records and exposes an adapter: given a record id, it returns the original record and can re-evaluate the falsifier against what has happened since.

Making a claim

A claim names a level and version and is reproducible by running the public suite:

Conforms to FJP-CONF v0.1, Level 2.

The gate is not the vendor's word. It is a runnable check against observable output.

What conformance does not assert

  • Not that a judgment is correct.
  • Not that an action is wise.
  • Not that the agent is safe in every operating context.
  • Only that the judgment has been externalized in a traceable, challengeable and re-evaluable form.

A triggered falsifier indicates that the judgment should be reconsidered. A falsifier that has not triggered does not independently establish that the original judgment was correct.

Implementation privacy

Conformance is deliberately separated from implementation. The public record may be inspected and tested while the mechanism that produced it remains private.

FJP-CONF tests the contract, not the recipe. Prompts, models, scoring, calibration, policy-selection logic, evaluators, orchestration, heuristics, proprietary data, and other implementation details are outside the conformance surface.
